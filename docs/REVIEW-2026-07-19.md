# 業界標準比較レビュー統合報告 + 修正指示書（2026-07-19）

3系統の集中レビュー（練習UX / 音声・タイミング /
MusicXMLインポート）と業界標準リサーチ（Synthesia / MuseScore / SmartMusic /
flowkey / Simply Piano / Yousician / Piano Marvel / Playground Sessions /
PracticeBird /
osmd-audio-player）の結果を統合したもの。**各指摘は実コードで裏取り済み**（file:line 付き）。着手する際は該当ファイルの現状を必ず再確認すること（このレビュー以降に行番号がずれている可能性がある）。

## 総評

wait-mode（guided）・テンポ調整・片手練習・カウントイン・お手本再生・セクション練習・進捗トラッキング・譜読み支援は業界標準を満たしており、KPコーチング／feed-forwardスキャフォールド／自己評価は標準を超えている。一方で
**ループ練習とポーズの欠如**が最大のギャップ。実バグは「カウントイン長の値渡し固定」と「リピート曲のセクション境界ずれ」が最重要。

## このレビューと同時に実装済み（2026-07-19 対応不要）

- **おともパート再生（Voice等の練習対象外パートの自動再生）**: 多パート譜を「練習パート（ピアノ）/ おともパート」に自動2区分。`pickPracticeStaffPlan`
  （note-extractor.ts）が 2段譜+4 / 鍵盤名+2 /
  GMピアノ族音色+2 で採点し、非鍵盤パートは `song.backingNotes` へ分離 →
  listen/rhythm で専用シンセ（sine系、ゴースト比 -3dB）により再生。レーン・採点・進捗には不関与。SmartMusic の My
  Part/Accompaniment モデル + 子ども向け「ミキサーを出さない」パターンに準拠。サンプル譜（Voice+Piano,
  53小節）で実OSMD検証済み。
- **リピート2重抽出の修正**: 抽出ウォーク中のみ
  `CursorIgnoreRepetitions=true`（finallyで復元）。リピート区間ノートの同時刻2重抽出（偽×2バッジ・伴奏2重発音の原因）を解消。
- **タイ終端判定の修正**: OSMD 1.9 の `Tie` に `EndNote`
  は存在しない（`Tie.Notes` 配列の末尾が終端）。終端ノートに両フラグが付いて
  `mergeTiedNotes` が同音の後続タイまで過剰併合していたのを修正。
- **stopPracticeAudio に releaseAll**:
  quit 後の鳴り残り（発音済みエンベロープ）を明示解放。

## P0 — 実バグ（全曲・毎セッション影響）

### 1. カウントイン長が初期値 4000ms のまま採点系に固定される

- 【症状】bpm≠60 の全曲で、guided のクロック凍結境界・早押しゲートが実際のカウントイン長とズレる（最大±1.6秒）。bpm>60 ではノーツがヒットラインを通り過ぎてからスナップバック、bpm<60 ではカウントイン中の打鍵が dt=0 の PERFECT として先行クレジットされる。
- 【原因】`packages/web/src/shell-practice.ts:149` — `_practiceScoring` の
  `tuning: { ..., countInMs: COUNT_IN_MS }` が**数値スナップショット**。
  `recomputePracticeTimings()`
  はシェルの let しか更新しない。他の消費者は全部サンク渡しなのにここだけ値渡し。使用箇所は
  `practice-scoring.ts:153-161`。
- 【指示】tuning オブジェクトを `get countInMs() { return COUNT_IN_MS; }`
  の getter に変える（`PracticeScoringTuning` 型は `countInMs: number`
  のままで getter を満たせるので scoring 側の変更不要）。回帰テスト:
  scoring 生成後に countInMs を変更し guided の `practiceElapsedMs()`
  境界が追従することをassert。

### 2. リピート曲でセクション境界が「ソース時計」のまま（同梱2曲該当）

- 【症状】`|: :|` を含む曲（fur_elise /
  alla_turca 両方該当）で、最初のリピート以降のセクション境界が繰り返しの合計時間ぶん手前にずれ、セクション B の練習に A の繰り返し末尾が混入・B の末尾が欠ける。
- 【原因】`packages/web/src/score-loader.ts` — ノートは
  `expandNotesByPlaybackOrder` で展開後時計に載るのに、
  `buildSectionsFromDefs(expanded, totalSec, sectionDefs, srcMeasureStartSec)`
  へ**ソース時計**の `srcMeasureStartSec`
  を渡している（`auto-section.ts:240-245` が
  `startSec = measureStartSec[d.startMeasure]`）。
- 【指示】`@piano/core` の playback-order.ts に「order を一巡して各ソース小節の
  **初回出現**時の累積秒を記録する」純関数（例
  `expandedMeasureStartSec(order, {startSec, durSec})`）を追加し、score-loaderからはその結果を
  `buildSectionsFromDefs` に渡す。累積計算は `expandNotesByPlaybackOrder`
  内部と同一ロジックを共有すること。回帰テスト:「リピート後の小節を startMeasure とするセクションの startSec が展開時計になる」ケースを
  `packages/core/tests/section-builder.test.ts` に追加。

### 3. volta 番号のカンマ表記（`number="1,2"`）で曲の残りが消える

- 【症状】`<ending number="1,2">`
  は正規の MusicXML。現状は raw 文字列キー完全一致のため、2括弧探索が全滅すると
  **volta 以降の全小節が playback
  order から脱落**し曲が途中で終わる（order に無い小節のノートは黙って捨てられる）。
- 【原因】`packages/core/src/library/playback-order.ts:108-114`（raw キー登録）と
  `:183-189`（`'1'`/`'2'`/`'3'` 完全一致参照）。
- 【指示】`num.split(',').map(s => s.trim())`
  で正規化して番号ごとに登録。スキップ探索は「'1' を含まない ending 開始 or
  ending 外」への一般化。探索が末尾まで走ったら「skip せず素通し」フォールバックで切り捨てを防ぐ。テスト:
  `number="1,2"`
  / 空白付き / マッチしない2括弧の3ケース追加（現状カバレッジ0）。

## P1 — 音・判定の正しさ

### 4. カウントインのクリックがテンポと無関係（実効BPM>100で常時）

- 【原因】`practice-state.ts:740-749`
  が合計時間をクランプ（2400〜7000ms）するのに対し、`audio-scheduler.ts:58`
  が**クランプ後の合計を4等分**してクリック間隔を導出。GO を境にテンポが不連続になる。
- 【指示】クリック間隔は常に実ビート
  `beatMs`、クランプはクリック**数**で吸収（`computePracticeTimings` が `beats`
  を返し、クリックは `countInMs - (beats - i) * beatMs` の末尾アンカーで配置）。

### 5. カウントインのビープがキャンセル不能 + ▶ 二度押しレース

- 【原因】(a) `audio-scheduler.ts:60-63`
  — ビープはコンテキスト絶対時刻に直接スケジュールされ `Transport.cancel()`
  の射程外。quit 後も鳴り切る。(b) `boot-session.ts:94-118` —
  `state.running===true` 分岐だけ `state.starting` ガードが無く、二度押しで
  `startPracticeSection` が並走。
- 【指示】(a) ビープを `Tone.Transport.schedule`
  の相対時刻に移し、guided でも Transport を start する。(b) ハンドラ全体を
  `state.starting` でガード（`transitionToSection` と同型）。

### 6. 「設定パネル中は練習が止まる」という文書化済み不変条件が未実装

- 【原因】`state.running`
  を false に戻すコードが**存在しない**（grep で書き込み箇所ゼロ）。練習中に ⚙ を開くとモーダルの裏で全ノートが miss になる。CLAUDE.md の invariant 記載と実装が乖離。
- 【指示】`practice-visibility.ts` の freeze/resume（クロック凍結 +
  `Transport.pause` + `startAudioTime`
  リベース）をモーダル用に一般化し、settings-panel の open()/close() から呼ぶ。`isSessionRunning`
  は凍結中 false を返すこと。これが入ると業界標準の「ポーズ」機能（P2-13）の基盤にもなる。

### 7. D.C./D.S. 曲で最終小節長が 72BPM デフォルト換算になる

- 【原因】`packages/web/src/playback-order.ts:115-123` —
  XML 経路でも最終小節だけ OSMD形状フォールバック。D.C. で巻き戻る曲は2周目全体が後ろへずれる。
- 【指示】`ScoreLoaderDeps.expandNotesByPlaybackOrder` に
  `sourceMeasureDurSec?: number[]` を追加し、score-loader から
  `xmlMeasureTiming.durSec` を渡して最優先で使う。

### 8. コーダ／セーニョが記号要素だけの譜面でジャンプ不発

- 【原因】`playback-order.ts:132-146` — `<sound coda="..">` 属性のみ対応。
  `<direction-type><coda/>` 記号のみの譜面（普通に存在）で To
  Coda 不発。measure 直下 `<sound>` も未対応（score-timing.ts とは非対称）。
- 【指示】記号要素の収集 + measure 直下 `<sound>` の属性走査を追加。

### 9. .mxl 内部ファイル名のバリエーションで解凍失敗

- 【原因】`user-songs-mxl.ts:105-115` — `full-path="…"`（二重引用符固定）と
  `endsWith('.xml')`（小文字・.xml のみ）。`score.musicxml`
  や大文字拡張子、シングルクォート container で「No score file inside .mxl
  archive」。
- 【指示】`/full-path\s*=\s*["']([^"']+)["']/` + 小文字化して `.xml` /
  `.musicxml` 両対応。テスト3ケース追加。

### 10. マイク入力時、和音の構成音が構造的に絶対ヒットできない

- 【原因】YIN は単音検出（`practice-tick.ts:238-242`
  は median ピッチ1音のみ）。和音セクションを Rhythm+マイクで練習すると chord-mate が全部 miss になり、理不尽な0★を食らう。警告・緩和なし。
- 【指示】`buildSectionNotes` 後（start-practice-section.ts の
  `computeHandRanges` 直前）に `!midiInput.enabled`
  なら「同時刻クラスタ（CHORD_MATE_TOLERANCE_MS 内）の最高音以外を
  `_filtered:true + hit:true`」にするマイク用フィルタを追加（hand
  filter と同じ既存メカニズムの再利用）。song-panel に「マイクでは和音は1音でOK」の説明行。

### 11. 判定タイムスタンプが「ハンドラ実行時刻」ベース

- 【原因】`midi-dispatch.ts:92` は `performance.now()`、
  `MIDIMessageEvent.timeStamp`
  は未使用。マイク経路は検出遅延（FFT窓+YINスロットルで最大~50ms）の補償項が無い。
- 【指示】段階導入: (1) `matchNoteOnset(midi, isExact, eventLagMs)` に
  `performance.now() - e.timeStamp` を渡して dtSigned から減算。(2)
  `MIC_INPUT_LATENCY_MS` 定数（40〜50ms）を tuning に追加。

## P2 — 業界標準機能ギャップ（優先度順）

### 12. ループ練習（最重要ギャップ）

flowkey / Simply Piano / Piano Marvel / Synthesia 全てが持つ中核機能。
`practice` に `loopOn`
を追加（practice-state-init.ts）、practice-tick.ts のセクション完了検出で
`loopOn` なら `completePracticeSection()`
の代わりに同セクションを再スタート（`transitionToSection`
の再入ガード経由）。UI は song-panel の ghost/metronome トグルの並びと練習中バーに1個ずつ。
**子ども発のトグルにすること（強制反復は banned-list 抵触）**。発展形の小節範囲ループは
`buildSectionNotes` の `[startSec, endSec)` スライスに `measureIdx`
サブ範囲を渡すオーバーロードで薄く実装できる。

### 13. ポーズ（P1-6 と同一基盤）

practice-visibility.ts の freeze/resume をエクスポートし、ptb バーに ⏸ を追加。ポーズ中は practice-tick の auto-miss ループをガード。

### 14. guided の支援強化

(a) 詰まったら数秒後に正解音を小さく1回鳴らす（`getInstruments()`
の piano を再利用。ペナルティなし）。(b) ゴースト・メトロノーム行を guided にも開放（song-panel-render.ts:269 の
`showRhythmOpts`）。

### 15. テンポ 50% の追加

TEMPO_STEPS（song-panel-render.ts:119）と TEMPO_TIERS（practice-state.ts:628）に 50 を追加し、defaultSongProgress（practice-progress.ts:97）で初期解放。
**「遅くする」は支援であって報酬ではない — 新たなアンロック条件を付けない。**

### 16. メトロノーム/カウントインの拍子追従

`beat % 3 === 0` ハードコード（audio-scheduler.ts:123）を
`SectionPlaybackOptions.beatsPerMeasure`
に。スコアロード時に拍子を song レコードへ格納（auto-section.ts の `<time>`
検出ロジック流用）。カウントインの拍数（常に4打）も同値に連動。P1-4 と同時に着手するのが効率的。

### 17. Rhythm モードの誤鍵可視化

practice-scoring.ts の `!matched`
分岐（229-234）で rhythm 時も低刺激チップ（300ms スロットル）。**減点・シェイム文言は追加しない（banned-list）**。

### 18. 結果カードから「条件を変えて再挑戦」

0★時に既存 `PianoCore.planSectionScaffold`
を呼び、戦略対応のワンタップボタン（`#resRetrySlow`）を結果カードへ。song-panel-render.ts:328-355 の apply ロジックが流用可能。時間圧をかけない（常設・無期限）。

### 19. 練習時間トラッキング

`completePracticeSection` で `practiceRealElapsedMs()` ベースの所要分を
`PracticeProgress.minutesByDay: Record<dateKey, number>`
に累積。ジャーナルのカレンダータブに当日分と生涯累計。**累積のみ・減らない数字・日次目標未達表示なし・保護者ダッシュボード化しない（banned-list）**。

### 20. 練習設定の曲ごと永続化

`SongProgress` に `lastSettings?: { mode, tempoPct, handFilter }`。 `selectSong`
の guided 強制リセット（select-song.ts:144）は「初回のみ guided、2回目以降は記憶値」に変更。

### 21. XML 系パーサの partEls[0] 固定を解消

score-timing.ts:140-142 / playback-order.ts:100-102 / musicxml-meta.ts:46-47 /
auto-section.ts:58-61 が**先頭パート（歌+伴奏譜では Voice）固定**。テンポ記号がピアノパート側にだけある譜面でテンポを取りこぼす。各関数にオプション引数
`partIndex`（既定0で後方互換）を追加し、score-loader が `pickPracticeStaffPlan`
の結果（練習パートの XML パート index）を渡す。

### 22. レイテンシ較正ウィザード

手動 ms スライダー（settings-panel.ts:173-193）は小学生には使えない。「クリックに合わせて10回タップ → 中央値を
`prefs.audioOffsetMs` へ」のガイド付き較正を追加（`scheduleCountInBeeps` +
`practiceRealElapsedMs` 流用）。

### 23. お手本音源の品質・表現

(a) triangle 波 PolySynth を
`Tone.Sampler` + 自己ホストのピアノサンプル数点に置換（CSP 制約に注意、`await sampler.loaded`
を待つ）。(b) `SchedulerNote` に velocity を追加して `triggerAttackRelease`
第4引数へ（MusicXML
dynamics 抽出も含む）。(c) おともパート音源も同時に差し替え候補。

### 24. 防御・小物（まとめて1タスク可）

- PolySynth `maxPolyphony: 64` 明示 + 超過時 remoteLog（現状 32 で脱落リスク）。
- `addFromBlob` にサイズ上限（URL 経路の 20MB と同文言）、`unzipMxlToXmlText`
  の解凍後サイズ上限（zip bomb 対策）、抽出 20,000 ステップ上限到達時の警告。
- grace/cue ノートのスキップ（`ve.IsGrace` / `note.IsCueNote`）—
  XML タイミング側は既に grace を除外しており非対称。
- `<repeat times>` 属性（3回以上の反復）対応。
- トリルのゴースト再生（×N クラスタを `durMs/replayCount`
  間隔で再展開するか、仕様としてコメント明記）。
- 成長チャートのテンポ混在（履歴に tempoPct はあるのにチャートが 60% と 100% を同一軸比較 — 「Best
  yet!」判定の公平性）。

## banned-list 抵触注意（全タスク共通）

- ループ/ヒントは**子ども発**のトグル。「★3までループ解除不可」等の強制反復禁止。
- テンポ下方向は常時開放。報酬化・新アンロック条件の追加禁止。
- 誤鍵フィードバックは可視化のみ。減点・"Wrong!" 系文言・赤×連発禁止。
- 練習時間は lifetime 累計と当日分のみ。減衰・未達表示・親が引き出す UI 禁止。
- 再挑戦導線に時間圧をかけない。進捗バーには必ず到達可能な終点を定義する。

## 参考: 業界標準リサーチ要点（おともパート設計の根拠）

- 練習対象外パートは**デフォルトで鳴らす**のが標準（Synthesia Background /
  SmartMusic Accompaniment / MuseScore・PracticeBird は全パート再生が既定）。
- ユーザー演奏時、自分のパートはアプリから鳴らさない（採点干渉回避を含む。Playground
  Sessions は demo 自動OFF）。
- 歌パートの音色は練習系ではピアノ系で代用が実績（SmartMusic）。GM 54 Voice
  Oohs をそのまま使う設計は主流でない。
- 子ども向けはミキサー UI を出さず「パート選択が再生設定を兼ねる」（Piano
  Maestro / flowkey / Simply Piano）。
- 任意の follow-up:
  ⚙ に「おともの音 ON/OFF」1トグル（既定ON）だけ追加する余地あり（現実装は常時ON・トグルなし）。wait系モードで伴奏も一緒に待つ Synthesia 方式は将来課題（guided は現状伴奏なし）。
